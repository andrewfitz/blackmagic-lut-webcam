7Accessibility

Round 3 must keep everything the current app already does (dense .help strings, labels and values) and add the following.

  • Tally is never color-only. Every ring has a text badge (ON AIR · Program / NEXT / ON AIR · Zoom) and the strip repeats it ("On air in Program").
  • VoiceOver pictures: one element per picture, e.g. "Feed 1, on air in Program, recording 12 minutes 31 seconds, output". Overlay buttons are separate elements in reading order: identity, tools, signal, REC.
  • Meters: .accessibilityValue("Peak −9.8 dB, RMS −14.2 dB") per channel (existing behavior); updates throttled to 2 Hz for speech.
  • Reduce Transparency: glass becomes opaque windowBackgroundColor / controlBackgroundColor; picture overlays get a solid dark capsule.
  • Increase Contrast: rings 4 → 5 pt, separators full opacity, chips get borders.
  • Keyboard: full Tab order sidebar → toolbar → pictures → strips → status bar; ⌘1–⌘4 move focus between feeds; Space toggles the focused control; every action is in a menu with its shortcut.
  • Help text carried over: GPU % scope, bypass meaning, timecode modes, preview vs. camera output, Program limits.
  • Motion: no animated meters or pulsing REC with Reduce Motion; REC shows a static dot.

9Performance rules (non-negotiable)

These come from how the capture and monitor runtime works today (README "Monitor tools", MonitorCoordinator registration, the comment in UltracamApp). A layout that breaks them needs runtime changes first.

  • One main native preview stays mounted. The selected feed's previewRenderer view is never recreated by navigation, collapse or layout changes. Collapsing a strip doesn't touch the picture.
  • Other pictures are monitor surfaces. They use MonitorCoordinator.registerSurface and report isVisible = false when hidden, occluded, collapsed or frozen, so they do no GPU work.
  • Scopes mount only when on for that feed and visible; refresh 10/15/30 Hz per settings; adaptive quality may lower cadence under pressure.
  • The menu bar preview renders only while the dropdown is open (miniPreviewRenderer); closed means no frames enqueued. Dropdown thumbnails are monitor surfaces.
  • Sampling only while visible: status bar resources (1 Hz), recording counters (2 Hz while a take runs), diagnostics window counters. No timers when hidden.
  • Sidebar thumbnails are periodic stills (≤ 1 per 2 s) or omitted, never extra live renderers.
  • No per-frame SwiftUI state. Video frames never flow through observable state; overlays update on discrete events.
