8Accessibility

Keep everything the current app does (dense .help strings, labels, values) and add:

  • Measured contrast: overlay pills use a 74% dark backing so text stays ≥ 4.5:1 over bright video; tertiary text never carries values; chip state is a checkmark, not tint.
  • Tally is never color-only: every ring has a text badge (ON AIR / PROGRAM / NEXT) and the strip repeats it.
  • Keyboard reveal: focusing a picture (Tab or ⌘1–⌘4) shows its hover controls; collapsed-strip actions are in the ⋯ menu and the Record menu.
  • VoiceOver: one element per picture, e.g. "Camera 1, on air, recording 12 minutes, output". Cutting is a named action "Cut to Camera 2", never the default action. Meters expose .accessibilityValue("Peak −9.8 dB, RMS −14.2 dB").
  • Announcements: cuts ("Camera 2 on air"), recording stopped, signal lost while recording, drive low.
  • Reduce Transparency: glass becomes opaque; overlay pills solid. Increase Contrast: rings 4 → 5 pt, chip borders. Reduce Motion: static REC dot, no animated meters.
  • Targets: live controls ≥ 24 pt (chevron, Processing switch, record control).

9Performance rules (non-negotiable)

From how the capture and monitor runtime works today. A layout that breaks them needs runtime changes first.

  • One native preview per renderer. previewRenderer (window) and miniPreviewRenderer (menu) are bound to the selected camera and never recreated by navigation, collapse or layout.
  • Every other picture is a monitor surface (MonitorCoordinator.registerSurface), reporting not visible when hidden, occluded, collapsed or frozen. A refused surface shows a badge.
  • Scopes mount only when on and visible; adaptive quality may lower cadence under pressure.
  • The menu preview renders only while the menu is open.
  • Sampling only while visible: status bar resources 1 Hz, recording counters 2 Hz while a take runs, diagnostics while the window shows.
  • No per-frame SwiftUI state; overlays update on discrete events.
  • Appearance: system colors and materials only, so every surface follows Dark/Light automatically (each round-4 page renders both).
