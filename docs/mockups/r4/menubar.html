1Every state has the same shape: one custom view item on top (live preview, two mini previews, or a placeholder of the same height), then real menu items. At most about 14 rows before submenus, so it fits a 13" display.
2In Program mode the thumbnails only show tally (red ring = on air). Cutting is a menu row, "Cut to Camera 2 ⌃2" (D1), so a stray click on a picture never cuts the meeting. ON AIR shows only while a camera app is connected; the app can't know which one, so rows say "In use".
3Each camera's submenu holds that camera's controls: cut, recording, processing, effects, LUT, input, inspector, monitor window. Stop Camera asks first when it would end a recording (D3). Rows that can't run say why in place.
4In automatic mode a visible preview counts as demand and would start capture, so the waiting state shows a placeholder until "Show Live Preview". A failed start offers one explicit Retry, never a background retry loop.
5Recording problems are loud: signal lost while recording (h) and a full drive that ended the take (i) appear as banners with one action, and the menu bar icon gets a triangle badge.
6The status icon is a template image: monochrome, follows the menu bar appearance, and uses knock-out badge shapes (dot = recording, triangle = attention) instead of red/orange dots, which macOS reserves for privacy indicators.
